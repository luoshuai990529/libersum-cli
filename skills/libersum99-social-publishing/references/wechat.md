# 公众号：原文排版

## 内容与结构

保留原文文字和顺序。Markdown 标题转换为章节标题，加粗转换为适量高亮，列表保留层级，引用保留出处，代码保留内容和缩进。识别 `![说明](图片路径)` 与 `![[图片路径]]`，从用户附图中解析；必要图片缺失时询问，不输出未说明的占位符。

按原文需要采用：标题 → 正文章节 → 原有结尾 → 独立品牌署名。导语、编号、金句、图注均只在原稿已有时使用；不强制添加英文装饰词或引导关注。表格过宽时换成逐项对照，但保留字段与数据；长代码使用换行或用户同意的配图形式。

## 视觉实现

模板 `assets/template-wechat.html`。采用静态 HTML、内联样式，系统字体，正文约 18px、行高约 1.9～2，容器最大宽度 677px 并适配手机。不把每段包成卡片。

### 配色选择

- **清爽白底·蜘蛛红强调（默认）**：白底 `#FFFFFF`、墨色正文 `#1A1A2E`；章节标题以蜘蛛红 `#E84A5F` 作左侧色条，正文中的重点少量使用蜘蛛红，科技蓝 `#2B7FD8` 留给链接或信息标记，芯片黄 `#F4D758` 只作少量底纹。适合技术说明和连续阅读的长文。
- **暖色品牌**：暖奶白 `#FEFCF6` 或深奶 `#FAF6EB` 为底，墨色正文，蜘蛛红用于章节强调，科技蓝和芯片黄少量辅助。适合需要更明显暖调的品牌文章。

一篇文章选一套方案并贯穿全文；不要逐节换底色或把红、蓝、黄同时用于同等强度的标题。

### 章节标题样式

参考截图的层级关系，不复制截图文案：二级章节标题左侧加一条约 5px 的蜘蛛红竖线，文字用墨色粗体并与色条留出约 10～12px 间距；标题前后留出明显空白，后续正文直接落在底色上，不再包卡片。标题编号只保留原稿已有内容，不擅自补序号。三级标题用普通粗体或少量蜘蛛红强调，不重复竖线，以保留层级差异。标题换行时保证行距舒适，竖线随标题高度延展即可。

用 section 分区和 p、h1/h2/h3、span、strong、em、a、br、img 等基础元素，避免复杂定位、脚本和依赖外部 CSS。这里是本 Skill 的保守输出约定，不是对平台完整标签白名单的声明。

本地图片随源文件保存，导出脚本会生成内嵌图片版；base64 用于本地自包含预览，不能保证编辑器接收图片。可复制 HTML 不等同于原始 HTML 代码粘贴：在浏览器选择渲染后的正文再复制。

## 交付与验收

- 源目录：`source.md`、可修改的 `index.html`、`assets/`。
- 导出目录：`article.html`（内嵌图片的浏览器预览）、`article-fragment.html`（正文片段）、`preview.png`、`report.json`。
- 对照原稿逐段核对文字、链接、引用、代码和图文对应关系，说明署名区是品牌附加内容。
- 390px 手机宽度无横向溢出，检查全文所有段落与图片；标题、正文与高亮有明确层级。
- 发布前实际复制到微信公众号编辑器检查样式与图片；如图片不保留，使用源目录中的图片逐张上传并替换，再检查手机预览。
- 本次未操作编辑器时，交付说明明确写“本地排版已检查，公众号粘贴与手机预览待确认”，不声称已可无损粘贴或已发布。
