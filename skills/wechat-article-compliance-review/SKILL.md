# 公众号文章规范审核

审核既有公众号文稿，产出可执行的发布前风险报告。它审查可见文案、图片/链接描述和用户提供的落地页信息；不代替微信后台审核、法律意见或行业资质审查。

## 输入边界

- 接收正文、标题、封面/配图说明、链接文案与目标地址、二维码去向、商业合作和账号主体信息。
- 缺少链接或图片落地页时，只评价文稿中可见的承诺与引导，并在报告中列为待核验项；不得假定目标页安全或合规。
- “能否插入某种链接、卡片或小程序”是目标账号的实时后台权限问题。审核时不把它当作已获准的能力。

## 审核流程

1. 阅读 [规则基线](references/policy-baseline.md)，将标题、正文、链接、图片、二维码、结尾和广告标识分开检查。
2. 只报告能由原文支持的风险。每项保存原文短引、位置、风险等级、规则依据、原因和最小修改建议。
3. 风险等级使用：**阻断**（发布前必须删除或取得资质/授权）、**高**（明显违反或高度可能误导）、**中**（取决于事实、落地页或标识）、**低**（质量/透明度问题）。没有问题的项目不凑数。
4. 对金融、医疗、药品、教育、募捐、时事政策、未成年人、商品交易等专项主题，明确写“需专项核验”，不要以本 Skill 替代许可证、广告审查或监管判断。

## 报告格式

按以下顺序输出，不改写原稿：

1. **发布结论**：可发布 / 修改后复审 / 暂缓发布，以及决定性原因。
2. **审核范围**：收到与未收到的素材；“仅审文稿”或“已审可见落地页信息”。
3. **风险清单**：使用五列 Markdown 表格，表头固定为 `等级｜位置｜原文短引｜判断与依据｜最小修改建议`。依据使用 [规则基线](references/policy-baseline.md) 的规则编号与官方链接。
4. **待核验项**：区分“后台功能待预览”“落地页待人工打开”“授权/资质待提供”，不要把待核验写成违规事实。
5. **发布前动作**：先列阻断和高风险项，再列手机预览、链接去向、授权和标识检查。

## 关键判断

- 文章互链、小程序卡片、二维码或“阅读原文”本身不自动违规；当当前页缺少核心信息，或用不实/仿冒/奖励驱动点击时，才按导流风险处理。
- 链接文字、按钮和跳转结果必须一致。“展开全文”跳下载页、“系统通知”样式图片跳其他页，属于高风险误导模式。
- 商业合作不因使用“合作”“推荐”而当然合规；构成广告时应检查广告标识、审核和专项资质。
- AI 署名不能替代事实核验、广告标识、来源、授权或风险提示。

## 完成条件

报告必须让编辑无需猜测即可知道：哪些句子/素材需要处理、为什么、改到什么方向，以及哪些结论仍取决于后台、落地页或资质。引用官方规则链接，且不声称已完成公众号后台或手机端验收。
